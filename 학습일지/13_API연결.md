## 💡 새로 배운 개념

- **API** — 다른 서비스의 주방에 들어가지 않고, 정해진 창구로 데이터를 주문하는 방법
- **요청과 응답** — 주소(`/weather`) + 옵션(`?city=서울&key=...`)으로 주문서를 보내면, JSON이라는 표준 포장 상자에 담겨 답이 온다
- **상태코드** — 200 성공 / 401 키 없음·틀림 / 404 없는 것. 답의 '내용'보다 먼저 '번호'를 보면 무슨 일이 일어났는지 안다
- **`localhost`와 포트** — localhost는 내 컴퓨터, 8765는 창구 번호
- **`curl`** — 브라우저 없이 터미널에서 API에 요청 보내기. `-i`는 영수증(상태코드)까지 보기
- **URL 인코딩** — 주소에는 원래 영어·숫자만 쓴다. 한글은 `%EC%84%9C...`처럼 포장해야 서버가 제대로 읽는다 (`--data-urlencode`, 파이썬은 `urlencode`)
- **`try / except`** — "해 보고, 안 되면 이렇게 해". 한 도시가 실패해도 다음 도시로 넘어가 전체가 멈추지 않는다
- **`timeout`** — 답이 없으면 무한정 기다리지 않고 포기하기
- **API 키를 코드에 쓰면 안 되는 이유** — 코드는 GitHub에 공개되는 파일이라, 키를 적으면 회원카드 번호를 게시판에 붙이는 것과 같다 → 키는 `.env` 금고에, `.env`는 `.gitignore`에
- **공공데이터포털 활용신청** — 개인/프로젝트 서비스키 중 선택, 자동 승인 API는 바로 키가 나온다. 요즘은 Encoding/Decoding 구분 없이 '일반 인증키' 하나만 보여 준다
- **기상청 격자 좌표** — 위도·경도 대신 전국을 5km 바둑판으로 나눈 칸 번호(nx, ny)로 위치를 부른다 (서울 60, 127)
- **실황 vs 예보** — 실황은 실제로 잰 값. 매시 정각 관측값이 40분쯤 뒤에 올라와서 45분 전이면 한 시간 전 값을 받는다
- **기록 쌓기와 중복 방지** — 파일 맨 아래에 덧붙이되(`"a"` 모드), 같은 관측 시각·같은 도시는 건너뛴다

## 📝 포트폴리오 한 줄

- **문제:** 여러 도시의 날씨를 확인하려면 사이트를 하나씩 찾아보고 손으로 옮겨 적어야 했다
- **해결:** 파이썬으로 기상청 공공 API에 연결해 7개 도시의 현재 기온·습도·강수를 한 번에 받아 표로 정리하고, 결과를 CSV에 중복 없이 쌓도록 자동화. 인증키는 `.env`로 분리하고 서버 오류·없는 도시도 멈추지 않게 처리
- **효과:** 7개 도시 날씨 확인·기록 수작업 약 10분 → 명령어 한 줄로 몇 초, 매일 실행하면 날씨 데이터가 저절로 쌓임

## 💬 느낀 점

- 오늘은 API를 연결하는 법을 배웠다. API는 다른 서비스의 데이터를 가져와 내 프로그램에 연결해 주는 통로다.
- 날씨·지도·결제·공공데이터·AI까지, API만 연결하면 거의 모든 일을 자동화할 수 있다는 걸 알게 됐다. 오늘은 기상청 데이터 하나를 연결했을 뿐인데, 같은 방법으로 다른 서비스들도 얼마든지 이어 붙일 수 있다.
- 이걸로 정말 많은 일을 해낼 수 있을 것 같다. 앞으로 어디까지 발전시킬 수 있을지, 그 가능성이 무궁무진하다고 느꼈다.
