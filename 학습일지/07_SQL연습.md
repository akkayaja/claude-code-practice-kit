## 💡 새로 배운 개념

- **SQL 쓰는 순서:** `SELECT → FROM → JOIN → WHERE → GROUP BY → ORDER BY → LIMIT`
- **엑셀과 비교하면:** `WHERE` = 필터, `ORDER BY` = 정렬, `GROUP BY` + `SUM`/`AVG`/`COUNT` = 피벗테이블, `JOIN` = VLOOKUP
- **데이터는 여러 표로 나뉘어 있다:** 주문표에는 고객·상품 **번호**만 있어서, JOIN으로 이어 붙여야 이름과 금액을 알 수 있다
- **`LEFT JOIN` + `IS NULL`:** 짝이 없는 줄(주문 안 한 고객)을 찾는 방법
- **`CASE WHEN`:** 조건에 맞으면 1, 아니면 0 → 반품 개수 세기 (엑셀 IF)
- **`WITH` + `RANK() OVER (PARTITION BY …)`:** 중간 결과를 임시 시트처럼 두고, 그룹마다 따로 순위 매기기
- **합계는 사람 수에 끌려간다:** 비교할 때는 1인당 평균도 함께 본다
- **같은 질문도 기준을 먼저 정해야 한다:** 완료 주문만 셀지, 수량인지 금액인지에 따라 답이 바뀐다
- **사람은 이름이 아니라 id로 구분한다:** VIP 중 '최지호'가 2명
- **SQL은 어디서 실행해도 같은 답:** 터미널(`sqlite3`)과 DB Browser 모두 울산 36명
- **파이썬에서 SQL 실행:** `sqlite3.connect` + `pd.read_sql_query`로 SQL 답을 표로 받아 그래프까지 그린다
- **두 방법으로 계산해 맞춰 보기:** 파이썬과 SQL의 반올림 방식 차이(6.2% vs 6.3%)를 비교 과정에서 찾았다

## 📝 포트폴리오 한 줄

- **문제:** 고객·상품·주문이 따로 저장된 쇼핑몰 데이터에서 매출 추이, 우수 고객, 반품이 많은 상품, 지역별 인기 상품을 알아내려면 여러 표를 일일이 대조해야 했다
- **해결:** SQL로 표를 JOIN해 15가지 질문에 답하고, 파이썬으로 같은 SQL을 실행해 그래프와 결론이 담긴 HTML 리포트를 자동으로 만들었다. 총액만 보지 않고 1인당으로 다시 계산해 "VIP 등급이 실제 구매력을 반영하지 못한다"는 점을 찾아냈다
- **효과:** 표 3개 · 주문 1,500건 분석을 SQL 몇 줄로 몇 초 만에 끝내고, 데이터가 바뀌어도 명령어 한 줄로 리포트를 다시 만들 수 있다

## 💬 느낀 점 (직접 작성)

- 이번 수업은 이전 수업과 비슷했지만, 엑셀로 다루기 어려운 많은 데이터 속에서 **의미 있는 데이터를 뽑아내는 과정**이라는 점이 달랐다.
- Claude Code를 쓰면 내 상황과 목표를 말로 설명하기만 해도, 그에 맞는 데이터를 뽑아 줄 수 있겠다고 느꼈다.
- 뽑은 숫자가 맞는지 검사하는 것도 Claude Code에게 맡길 수 있다. 다만 그 숫자가 **내가 원한 질문에 대한 답인지**는 나만 알 수 있다.
- 그래서 Claude가 결과를 줄 때 **"이런 기준으로 뽑았는데, 원하는 게 맞나요?"**라고 설명해 주고, 나는 그 기준이 내 의도와 맞는지 확인하는 방식이 가장 좋겠다고 생각했다.
