## 💡 새로 배운 개념

- **스킬 = 업무 매뉴얼.** Claude는 매뉴얼 전체가 아니라 맨 위 `description`(책등 제목표)만 늘 보고 있다가, 요청과 맞으면 그때 꺼내 읽는다 → 제목표에 "이렇게 말하면 써라" 예시를 적는 게 중요
- 스킬 이름은 영어 소문자·숫자·`-`만 (`weekly-report`). 한국어 이름은 설명에 적기
- 스킬·MCP 목록은 **대화를 시작할 때** 읽는다 → 만들거나 고친 뒤엔 새 대화에서 확인
- 매뉴얼에 기준을 베끼지 않고 **원본 파일을 가리키게** 하면(15번 템플릿), 기준을 한 곳만 고치면 된다
- **MCP = AI의 새 손.** `@mcp.tool()` 한 줄로 함수를 손으로 등록, 함수 아래 설명문은 Claude가 읽는 사용 설명서
- 손 이름은 영어·숫자·`_`만 쓸 수 있다
- `stdio` = 전화 통화처럼 표준 입출력으로 대화 → 서버에서 `print()`를 쓰면 대화가 꼬인다
- 최신 `mcp`는 2.x판: `FastMCP` → `MCPServer`로 이름이 바뀜 (예전 안내서와 다를 수 있음)
- `claude mcp add 이름 --scope project -- 명령` → `.mcp.json`(손 등록표). 상대 경로로 적으면 내 컴퓨터 경로가 안 들어감
- **자물쇠는 여러 겹:** 문지기(첫 단어 검사)는 속을 수 있다(`WITH … DELETE`). 파일을 보기 전용(`mode=ro`)으로 여는 게 진짜 벽
- 파일 **지문(해시)**: 한 글자만 바뀌어도 완전히 달라짐 → 시험 전후 비교로 "안 바뀌었다"를 증명
- **플러그인 = 선물 상자.** `plugin.json`(이름표) + `skills/` + `.mcp.json`(손 연결표), 저장소 맨 위 `.claude-plugin/marketplace.json`이 진열대 → 동료는 `plugin marketplace add` → `plugin install`
- 상자 안 경로는 `${CLAUDE_PLUGIN_ROOT}`, 동료 컴퓨터엔 `.venv`가 없으니 `uv run --with mcp`로 공구를 알아서 받게 함
- 원본과 상자 속 복사본이 어긋나지 않게 **포장 스크립트로 다시 포장**

## 📝 포트폴리오 한 줄

- **문제:** 주간보고·리뷰 응대처럼 반복되는 일을 매번 명령어와 규칙을 기억해 처리해야 했고, AI는 회사 DB를 볼 수 없었으며, 연결하더라도 데이터를 망가뜨릴 위험이 있었다
- **해결:** 업무 순서·양식·기준을 Claude Code 스킬 2개로 만들고, 매출·고객 DB 조회를 MCP 서버(읽기 전용 자물쇠 3겹)로 연결한 뒤, 플러그인으로 포장해 동료가 한 줄로 설치하게 함
- **효과:** "주간보고 써 줘", "지난달 매출 알려 줘", "이 리뷰 답글 달아 줘" 한마디로 처리 (명령어·기준 암기 불필요), DB 수정 시도 5/5 차단

## 💬 느낀 점 (사용자 말을 다듬은 초안)

**이번에 한 일에서 느낀 것**
- 스킬은 바로 이해됐는데, MCP는 API와 뭐가 다른지 헷갈렸다. 이야기를 나눠 보니 MCP는 API를 AI가 쓰기 좋게 감싸는 **공통 규격(손잡이)**이라는 걸 알게 됐다.
- API는 내가 "이 API를, 이 키로" 하고 가리켜야 쓰지만, MCP로 손을 달아 두면 "지난달 매출 알려 줘"라고만 해도 Claude가 **알아서 골라 쓴다.**
- API를 MCP로 만드는 것도 Claude에게 부탁하면 되고, 나는 **열쇠(API 키)와 기준만** 정하면 된다.
- 자물쇠는 한 겹이면 뚫릴 수 있다. 문지기를 속인 `WITH … DELETE`를 '보기 전용' 자물쇠가 막는 걸 보고, AI에게 데이터를 맡길 때는 **여러 겹으로 잠가야** 한다는 걸 배웠다. *(Claude 보탬)*
