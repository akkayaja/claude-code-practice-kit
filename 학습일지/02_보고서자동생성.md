## 🔢 결과 숫자 (내 눈으로 검증한 것)

- 파일 **5개** × 12줄 → 합친 결과 **60줄**
- 11월 전체: 완료 **17건**, 달성률 **28.3%** (17 ÷ 60 × 100)
- 영업1팀 완료 **5건** — 엑셀 `=COUNTIF(E:E,"완료")`로 직접 센 숫자와 **일치**
- 팀별 완료 5 + 4 + 4 + 2 + 2 = **17** — 전체 완료 건수와 **일치**
- 이슈 **32건** + 이슈 칸이 빈 줄 **28줄** = 60줄, 이슈 목록에 빈 칸 **0개**
- 3주차만: **15건** 중 완료 **4건** (달성률 **26.7%**), 이슈 **9건** — 다른 방법으로 미리 세어 둔 정답과 **일치**
- 지연 주의 팀: 11월 전체는 **영업1팀·운영팀**(각 지연 5건, 41.7%), 3주차는 **마케팅팀**(지연 2건, 66.7%)
- 주차 없이 다시 실행해도 60 / 17 / 28.3% 그대로 (새 기능이 원래 기능을 망가뜨리지 않음)

## 💡 새로 배운 개념

- `glob("*_실적.xlsx")` + `pd.concat` — 이름 규칙이 같은 파일을 모두 찾아 한 묶음으로 합치기. 합치기 전에 파일 이름에서 팀 이름을 떼어 `팀` 칸(모둠 스티커)으로 붙여 둔다
- `groupby("팀").agg(...)` — 같은 팀끼리 모아서 팀마다 개수 세기 (엑셀 피벗과 비슷)
- 빈 칸은 `NaN`(값 없음)으로 읽힌다 → `fillna("")` + `str.strip()`으로 공백만 있는 칸까지 걸러 낸다
- **템플릿 채우기** — 양식의 `{{이름}}`을 `replace`로 바꾸고, `assert`로 빈칸이 남았는지 검사
- `sys.argv` — 실행할 때 뒤에 붙인 말(`3주차`)을 프로그램이 받아 쓰기
- **개수보다 비율** — 크기가 다른 기간(12건 vs 3건)을 같은 자로 비교하려면 비율로 잰다
- 달성률 1등(영업1팀)이 지연 경고도 받을 수 있다 → 숫자 하나만 보지 말고 여러 각도로 봐야 한다
- `python-docx` — 빈 Word 문서를 펴고 제목·문단·표·목록을 한 줄씩 써 넣어 저장
- **검산 습관** — 엑셀 COUNTIF, 합계 맞추기, 회귀 테스트(원래 기능 다시 확인)로 프로그램 결과를 믿을 수 있는지 확인
- `pip`(공구 사 오기)과 `python`(공구로 일하기)은 다른 명령이다

## 📝 포트폴리오 한 줄

- **문제:** 각 팀이 보낸 실적 엑셀 5개를 손으로 열어 세고, 표로 정리하고, 이슈를 골라 보고서 양식에 옮겨 적어야 했다
- **해결:** 파이썬(pandas) 스크립트로 취합 → 달성률·팀별 표·이슈 목록 계산 → 양식 자동 채우기 → Word 저장까지 한 번에 처리하고, 주차 선택과 지연 팀 자동 강조 기능을 추가
- **효과:** 수작업 취합·작성 → 명령어 한 줄로 몇 초 만에 .md와 Word 보고서 완성, 주차별 보고서도 `3주차`만 붙이면 바로 생성

## 💬 느낀 점 (직접 작성)

- 흩어진 여러 파일을 하나로 모으고, 정해진 양식에 맞춰 필요한 숫자와 내용만 뽑아내는 흐름을 처음부터 끝까지 직접 실행해 봤다.
- 회사에서 각 과의 실적을 취합해 보고서를 올릴 때 바로 써먹을 수 있을 것 같다. 파일을 일일이 열어 세고 옮겨 적던 일을 명령어 한 줄로 끝낼 수 있다는 게 가장 인상적이었다.
- 프로그램이 낸 숫자를 엑셀 COUNTIF로 직접 맞춰 보면서, 자동화는 '돌리는 것'보다 '결과를 믿을 수 있는지 확인하는 것'이 더 중요하다는 걸 느꼈다.
