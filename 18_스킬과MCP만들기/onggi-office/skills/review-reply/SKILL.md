# 리뷰-답글 (업무 매뉴얼)

> 판단 기준과 말투는 **15번 템플릿 원본 한 곳**에만 적혀 있다:
> `15_프롬프트템플릿/템플릿_v4.txt` (저장소 맨 위 폴더 기준)
> 이 매뉴얼은 기준을 따로 베껴 두지 않는다. 템플릿이 v5로 바뀌면 아래 파일 이름만 바꾼다.

## 0. 먼저 할 일
1. `15_프롬프트템플릿/템플릿_v4.txt`를 **끝까지 읽는다.** (역할·감정 기준·긴급도 기준·말투·금지사항·출력형식)
2. 요청이 아래 두 갈래 중 어느 쪽인지 고른다.

| 요청 | 갈래 |
|---|---|
| 대화에 리뷰 글을 1~5개 붙여 넣음 ("이 리뷰 답글 달아 줘: …") | **갈래 ① 바로 답하기** |
| "리뷰 전체 처리", "CSV 처리", 리뷰를 따로 주지 않고 전체를 말함 | **갈래 ② 코드로 전체 처리** |

## 갈래 ① 바로 답하기 (Claude가 직접, API 비용 없음)
- 템플릿의 **[출력형식] 4줄**을 리뷰마다 그대로 쓴다. 순서·이름을 바꾸지 않는다.
  ```
  감정: 긍정/부정/중립 중 하나
  답글: (고객에게 보일 답글)
  내부조치: [CS팀/상품팀/물류팀] 할 일 한 줄 (없으면 "없음")
  긴급도: 긴급 대응 필요/일반 중 하나
  ```
- 리뷰가 여러 개면 `[리뷰 1]`, `[리뷰 2]`처럼 머리줄을 달고 4줄씩 쓴다.
- 감정은 **별점이 아니라 내용**으로 정한다. 별점을 같이 줬어도 판단에 쓰지 않는다.
- 답글은 **3문장·150자 이내**. 답글 글자 수는 눈대중하지 말고 코드로 센다:
  `python3 -c "print(len('''답글 내용'''))"` → 150을 넘으면 줄여서 다시 센다.
- 4줄 아래에 **"판단 근거"** 한 줄을 덧붙인다. (예: "교환 요청 + 답 없음 → 템플릿의 '환불·교환을 요청함' 기준으로 긴급")
  이 줄은 사용자 확인용이고, 고객 답글에는 넣지 않는다.

## 갈래 ② 코드로 전체 처리 (15번 스크립트 그대로)
저장소 맨 위 폴더에서 아래 한 줄을 실행한다. Claude API 키는 03번 금고(`03_메일분류/.env`)를 빌려 쓴다.

```bash
cd "$(git rev-parse --show-toplevel)/15_프롬프트템플릿" && ../03_메일분류/.venv/bin/python 3_전체처리.py 템플릿_v4.txt
```

- 입력: `15_프롬프트템플릿/data/고객리뷰.csv` (칸: 리뷰번호, 별점, 리뷰내용)
- 결과: `15_프롬프트템플릿/결과/리뷰_답글_v4.csv` (실행할 때마다 덮어씀)
- 끝나면 화면의 요약(감정별 개수, 긴급 개수, 답글 최대 길이)을 **그대로 옮기고**,
  CSV에서 `긴급 대응 필요`인 리뷰만 번호·내용·내부조치로 표를 만들어 보여 준다.
- AI 결과는 실행마다 문장이 조금씩 달라진다. 감정·긴급 **개수**가 지난번과 다르면 어느 리뷰가 바뀌었는지 짚어 준다.

## 지켜야 할 규칙
- 템플릿의 [금지사항]을 그대로 지킨다: 답글 여러 버전 금지, 빈칸·가짜 연락처 금지, 환불·보상·날짜 약속 금지, 이모지·굵은 글씨 금지, 별점 이야기 금지.
- 리뷰 원본 CSV(`data/고객리뷰.csv`)는 고치지 않는다.
- 기준이 애매한 리뷰(템플릿 기준 두 개에 모두 걸림)는 혼자 정하지 말고 **두 가지 판단을 보여 주고 사용자에게 고르게** 한다. 정해지면 템플릿 새 버전(v5)에 적자고 제안한다.
- 답글을 실제로 어딘가에 올리거나 고객에게 보내지 않는다. 초안만 만든다.
