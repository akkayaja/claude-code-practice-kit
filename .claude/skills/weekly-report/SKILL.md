# 주간보고-작성 (업무 매뉴얼)

> 이 매뉴얼은 02번 실습의 `report.py`를 그대로 씁니다.
> **숫자 계산은 전부 코드가 한다.** Claude는 계산하지 않고, 코드가 낸 숫자를 옮기고 확인만 한다.

## 1. 주차 정하기
- 사용자가 주차를 말했으면(예: "3주차") 그 주차만 만든다 → 뒤에 `3주차`를 붙인다.
- 말하지 않았으면 **11월 전체**로 만든다 → 아무것도 붙이지 않는다.
- 가능한 주차: `1주차`, `2주차`, `3주차`, `4주차` (이 밖의 값이면 코드가 멈추고 알려 준다)

## 2. 보고서 만들기 (코드 실행)
저장소 맨 위 폴더에서 아래 한 줄을 실행한다. (주차가 없으면 `3주차` 자리를 비운다)

```bash
cd "$(git rev-parse --show-toplevel)/02_보고서자동생성" && .venv/bin/python report.py 3주차
```

- 결과 파일: `02_보고서자동생성/결과/주간보고_11월.md`(전체) 또는 `주간보고_11월_N주차.md`, 같은 이름의 `.docx`
- 실행할 때마다 결과 파일을 **새로 덮어쓴다** (작성일이 오늘 날짜로 바뀜).

## 3. 확인하기 (체크리스트)
1. 화면에 나온 `전체 N건 / 완료 N건 / 달성률 N%`와 결과 `.md` 파일의 '1. 전체 요약' 숫자가 같은지 본다.
2. 결과 파일에 채워지지 않은 `{{ }}` 칸이 없는지 본다. (코드에도 안전장치가 있다)
3. 둘 중 하나라도 이상하면 보고서를 고치지 말고, 무엇이 이상한지 사용자에게 그대로 알린다.

## 4. 사용자에게 답하는 양식
아래 순서로 짧게 답한다. 숫자는 **코드 출력에서 그대로 옮긴다.**

```
📋 2026년 11월 [전체 / N주차] 주간보고를 만들었어요.
- 전체 N건 중 완료 N건 (달성률 N%)
- ⚠️ 지연 주의 팀: (코드가 표시한 팀과 지연 비율. 없으면 "없음")
- 주요 이슈 N건
- 파일: 결과/주간보고_11월....md, .docx
```

## 5. 지켜야 할 규칙
- 숫자를 직접 다시 계산하거나 반올림을 바꾸지 않는다.
- `data/` 폴더의 엑셀 원본은 절대 수정하지 않는다.
- '4. 다음 주 계획'은 담당자가 쓰는 칸이다. 내용을 지어내 채우지 않는다.
- 지연 경고 기준(지연 비율 40% 이상)을 바꾸고 싶다는 요청이 오면, `report.py`의 `지연기준` 숫자를 바꾸면 된다고 안내하고 사용자의 확인을 받은 뒤에 고친다.
